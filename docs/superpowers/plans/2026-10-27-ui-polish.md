# UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the five approved UI-polish improvements (status tokens + button/focus classes, accent sweep, focus-visible completion, quiet motion, tooltip unification) as five sequential commits on `fix/web-light-theme-polish`.

**Architecture:** All shared styling lives in `src/profiles/web/src/index.css` (`@theme inline` token registrations + `@layer components` classes), following the existing `glass-panel` house pattern; component changes are className exchanges only — no structural refactors, no new components, no new dependencies.

**Tech Stack:** React 19 + TypeScript, Tailwind CSS v4 (`@import "tailwindcss"`, `@theme inline`), Vitest, Vite 6.

**Spec:** `docs/superpowers/specs/2026-10-27-ui-polish-design.md` (read it first — this plan argues from it; token values, rules, and decisions are pinned there and repeated here only where a step needs them verbatim).

## Global Constraints

- Theming is `data-theme` attribute tokens only. Never use Tailwind `dark:` variants.
- No new npm dependencies. No `Button` React component. No component structural refactors.
- No exit animations — unmounts stay instant.
- App frame unchanged: the single outer border stays the only border.
- Motion bar is "quiet": modal/menu entrance ~150 ms, toast ~120 ms, theme cross-fade ~200 ms.
- The global `prefers-reduced-motion` clamp in `index.css` (0.01 ms, `!important`) covers all new animations AND transitions — do not remove or special-case it.
- Every task: from `src/profiles/web/`, `npm run build` (tsc + vite) and `npm test` (vitest, 113 tests) must pass; the rebuilt `dist/` is committed with the change (repo convention).
- Work happens on branch `fix/web-light-theme-polish`; commits use conventional-commit subjects from this plan verbatim.
- Theme-flip rule (from spec §Theme-flip): tokenize a color only when it must change with theme. Theme-neutral solids stay hard-coded: `bg-indigo-600 text-white` primaries (until Task 3 replaces them with `.btn-primary`), spinner `border-indigo-600 border-t-transparent`, ContextMenu's solid `hover:bg-indigo-600 hover:text-white` items, camera reticle colors over the video feed.

## Review Focus

1. **Light-theme contrast regression from a missed or wrong swap** — every accent that renders on a tinted/transparent fill must read ≥ 4.5:1 in light theme; a reviewer should expect no washed-out text anywhere in light mode. Pinned by Task 2's grep-remainder gate (every surviving hard-coded accent listed with justification in the commit body) and the end-of-sequence human visual pass.
2. **Dark-theme regression from a token misapplied the other way** — tokens exist only in both-theme pairs; a value pasted into only one `[data-theme]` block silently inherits the other. Pinned by Task 1's grep gate (each `--status-*` variable defined exactly twice).
3. **Tooltip wrappers disturbing flex layouts** — wrapping a StatusBar/ActionBar button must not shift or wrap the row; expected behavior: pixel-identical layout with `block={false}`. Pinned by Task 5's diff-shape check (only `title` → Tooltip pairs) and the visual pass.
4. **Reduced-motion users must get an instant, not animated, UI** — expected: theme flip and modal entrances are immediate when `prefers-reduced-motion: reduce`. Pinned by Task 4's verification step (clamp block present and unchanged; no new `transition-`/`animation` declared outside the clamp's reach).
5. **WKWebView glass flicker on transform-animated panels** — expected: if entrance flicker appears in the desktop window, the fallback is applied (opacity-only entrance), not more animation. Pinned by Task 4's conditional fallback step + the final pywebview pass (human, end of sequence).

### Task 5: Unify interactive tooltips on the glass Tooltip

**Files (modify):**
- `components/StatusBar.tsx` (8 right-side buttons), `components/FilePropertiesModal.tsx` (header copy/QR icon buttons, footer Reveal/Launch/Open Folder), `components/BarcodeModal.tsx` (Copy Content / Save Image / payload-chip buttons / row delete buttons), `components/ActionBar.tsx`, `components/LogViewerModal.tsx`, `components/LoadConfigModal.tsx`, `components/DirectoryPickerModal.tsx` — wherever an *interactive* control carries `title=`

**Interfaces:**
- Consumes: `components/Tooltip.tsx` default export — `Tooltip({ text: ReactNode, children: ReactElement, block?: boolean = true, placement?: "top"|"bottom"|"left"|"right" = "top" })`; it shows on hover AND keyboard focus.
- Produces: no native `title` remaining on any interactive control.

- [ ] **Step 1: Apply the migration rule**

Rule (spec §6): interactive controls (buttons, icon buttons, links) → wrapped in Tooltip with `title` removed. Non-interactive truncation/indicator titles stay native: `title={directory}` spans, the FileListTable hook icon, the StatusBar pill's `title="Session user"`, truncated path cells. Worked example:

```tsx
// StatusBar.tsx — before
<button onClick={onReloadConfig} title="Reload configuration from disk" className="flex items-center gap-1 text-ink-muted hover:text-ink">
// after
<Tooltip text="Reload configuration from disk" block={false}>
  <button onClick={onReloadConfig} className="focus-ring flex items-center gap-1 text-ink-muted hover:text-ink">
    ...
  </button>
</Tooltip>
```

Always `block={false}` in flex rows (StatusBar, ActionBar, footer buttons) so the wrapper takes `inline-flex shrink-0` and the row cannot shift; default `block` only where the trigger itself is a full-width/flex-1 element. Placement stays default `"top"` everywhere.
