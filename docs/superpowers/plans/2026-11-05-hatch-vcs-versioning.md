# hatch-vcs Tag-Derived Versioning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the git tag the single source of truth for the version: no manual bump in `pyproject.toml`, lineage versions on non-tag builds, release flow (manual tag push) unchanged.

**Architecture:** hatch-vcs build hook derives a PEP 440 version from `git describe` at build time and generates `src/profiles/_version.py`. `pyproject.toml` declares `dynamic = ["version"]`. Runtime `__version__` keeps `importlib.metadata` as primary and swaps its pyproject-regex fallback for the generated module. CI builds get full git history (`fetch-depth: 0`) so the tag is visible.

**Tech Stack:** hatch-vcs (hatchling build hook wrapping setuptools-scm), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-05-hatch-vcs-versioning-design.md`

## Global Constraints

- Build backend stays hatchling; `[tool.hatch.build.hooks.custom]` (web dist) is untouched and must keep working.
- Tag naming convention unchanged: `vMAJOR.MINOR.PATCH[-pre]`. setuptools-scm's default tag regex already matches `v`-prefixed tags — no `tag-pattern` config needed.
- Config lives entirely in `pyproject.toml`; no new config files.
- Manual tag push stays the release trigger; no Commitizen.
- Branch: `feat/hatch-vcs-versioning`, PR against `main`.
- Project quality gates per AGENTS.md: `ruff format .`, `ruff check .`, `pylint src/profiles`, `pyright src/profiles`, `pytest`.

## Review Focus

- **Git-less source tree** (e.g. GitHub source-zip download, no `.git`, no build hook run): `import profiles` must not crash and must return `0.0.0-dev` as last resort. Pinned by `test_version_last_resort_when_no_vcs_module` (Task 3).
- **Missing/corrupted package metadata** (dist-info unreadable): the existing swallow-all behavior is preserved — no exception escapes `import profiles`. Pinned by `test_version_uses_vcs_fallback_when_metadata_missing` (Task 3).
- **Shallow CI checkout** (`fetch-depth: 1`, the Actions default): builds would silently produce a fallback version instead of the tag version. Pinned by grep verification over both workflow files (Task 4).
- **Guard must still reject non-SemVer tags**: `v1.0`, `1.0.0`, `v1.0.0-extra+meta`-style malformed refs. Pinned by the kept regex in `release.yml` (Task 4).
- **Editable-install staleness** (the old stale-egg-info bug): a fresh `uv sync` must yield a version matching the current commit lineage. Pinned by the end-to-end `uv build` wheel-name check (Task 5).

- [ ] **Step 3: Rewrite `_resolve_version`**

New body — resolution order `importlib.metadata` → `profiles._version` → `"0.0.0-dev"`, same swallow-broad-errors behavior for the metadata stage:

```python
def _resolve_version() -> str:
    """Return the package version.

    Resolution order: installed package metadata (dist-info), the
    hatch-vcs generated ``profiles._version`` module (editable/dev
    builds), then a development sentinel for git-less source trees.
    """
    from importlib.metadata import PackageNotFoundError, version

    try:
        try:
            return version("profiles-app")
        except PackageNotFoundError:
            return version("profiles")
    except Exception:
        pass

    try:
        from profiles._version import version as vcs_version
    except ImportError:
        return "0.0.0-dev"
    return str(vcs_version)
```

Docstring updated as shown (replaces the pyproject-parsing explanation). Remove the now-unused `from pathlib import Path` and `import re` module imports — verified used only by the old fallback.
